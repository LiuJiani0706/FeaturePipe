# 方法与复现边界

本项目依据提供的 FeaturePipe 研究手稿与提示词附录独立实现，不含原始实验代码、论文全文、图片或 Campus-Feature 私有采访语料。输入为报道标题与采访材料；独立生成评测不输入已发表正文。

## 两个程序版本

早期 `python3 -m featurepipe` 是简化版，保留用于演示与回归比较；`featurepipe.paper_experiment` 实现后续整理的附录协议。Skill 默认由当前助手执行可调整的写作流程，只有外部论文实验入口才调用该协议程序。

| 阶段 | 早期简版 | 论文实验器 |
| --- | --- | --- |
| 摘要与元提示词 | 来源摘要、专属指令和大纲 | 完整消息历史，按附录执行 |
| 大纲修复 | 一次局部修订 | 局部修订或返回元提示词重建，最多三次尝试 |
| 初稿及长度 | 本地计数、有限重试 | 保留旧版/论文版首次初稿，另存论文版长度补救 |
| 分句 | 本地正则 | 模型分句，JSON、顺序和覆盖率校验 |
| 逐句审阅 | 检查、建议与顺序修订 | 每句独立十二维检查，资深编辑汇总后顺序修订 |
| 全文清理 | 每轮一次 | 每轮五项，最多五个外循环 |
| 末次审阅 | 简版报告与可选同模型评价 | 外循环后增加一次只读审阅；五轮时为第六次 |
| 预算 | 调用数与字符/token 工程预留 | 额外共享人民币估算、请求前持久预留与进程锁 |

## 工程适配

中文执行模板是英文附录的中文回译，附录本身译自中文运行提示词；不能称为恢复原始中文字符串。出处、转换说明及源文本哈希见 `prompt_sets/paper-and-legacy-zh.json` 的 provenance。

HTTP 消息历史替代 Gemini 缓存会话，并发独立请求替代 Gemini Batch；分句增加可解析序列化格式与程序验证；篇幅以本地中文字符数为准并限制重试。评价另加独立模型，不冒充原论文生成步骤。按配置、检查点和完成报告判定执行范围，不能把预算中止或局部修订标为完整五轮。

每次检查提供完整采访与全文，长语料可能超出上下文，成本随素材长度、句数与轮数增加。分句覆盖率校验允许排除标题等附加材料，不保证语义上完全正确。

## 证据与评价限制

来源编号存在不代表它支持结论；直接引语字面匹配不检查归属或间接陈述。审阅建议、修订和润色都可能引入新错误。首次初稿、长度补救和多轮修订是不同干预，应分别保存与比较；旧版和论文版提示词本身也存在篇幅等差异。

本仓库尚未提供完整五轮论文实验与人工盲评的公开复验结果。私有真实案例仅有经范围缩减后的工程试验，不用于模型普遍能力排名。

研究手稿将 Ruowan Zhu 列第一作者、Jiani Liu 列第二作者。方法归属、程序实现和数据公开授权分别维护；代码许可不自动覆盖未发布论文与采访材料。
