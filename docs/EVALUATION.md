# 评估与后续方案

## 当前证据

已提供在线对照与审阅入口 `--evaluate`，实际调用与结果见本地 runs 目录；没有进行模型能力排名。离线 mock 和单元测试只验证程序行为；其固定短文不能证明事实忠实度、叙事质量或论文结果复现。真实模型评测需要可用服务凭证与已获授权的材料。

## 可执行评测设计

1. 使用合成或获授权并去标识的材料，每案例标注人物、引语、时间线及来源证据；参考文章单独保存，不进入生成输入。
2. 同一素材比较单次直写、完整五轮、单轮、整文检查四种设置；记录模型精确版本、参数、提示、调用量、实际 token、延迟、失败和成本。
3. 设置时间归属、引语错配、无依据场景等可控错误，测检查的精确率与召回率。不要仅让生成模型自评。
4. 请至少两位编辑盲评来源支持、人物代表性、叙事连贯性、修订工作量；报告分歧与案例级结果，不用少量样本宣称普遍优越。
5. 重复运行以测随机性，比较每轮新增与修复错误，预注册停止标准和成本上限。

## 下一步优先级

先建设证据账本：逐条事实关联素材 ID 和原文区间，检查引用是否存在，将需要补访和可直接修正分开。可恢复任务状态和阶段哈希缓存已实现，服务端返回的实际token已汇总；仍需处理超时请求用量未知等情况。

成本优化可先做确定性时间线与实体检查，按风险选择复查句子；这是增强模式，应与论文的全文五轮设定分别报告。长素材采用检索时必须评估漏检，不能默认为等价复现。

多 agent 可让事实检查、人物表述和结构编辑独立提出建议，由单一编辑顺序应用，防止并发覆盖。只有受影响段落复查通过才接受修订，并保留冲突和人工裁决。先以相同总 token 预算比较单 agent 与多 agent，再决定是否值得增加协作复杂度。

- 对照稿有无依据的现场开头及改写直接引语。流水线稿避开了该现场开头，但保留了无依据性别代词，修订还带来观点归属扩大风险。
